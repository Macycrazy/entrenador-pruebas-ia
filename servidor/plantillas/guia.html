📖 Cómo funciona

Dos caras: la explicación para quien viene a verlo, y las instrucciones para quien lo va a montar.

Esto es una inteligencia artificial entrenada aquí, con datos nuestros y sin depender de nadie.

No es una suscripción a un servicio de fuera ni una demostración grabada. Es un sistema real corriendo en este ordenador: aprende de ejemplos, se le puede ver aprender en directo, y lo que aprende se queda aquí dentro.

Cómo aprende una máquina, en cuatro pasos

Es más sencillo de lo que parece, y siempre es el mismo circuito, tanto para reconocer una cara como para predecir la asistencia del mes que viene.

1
🗂️

Ejemplos

Se le dan miles de casos ya resueltos. Aquí, casi cien mil fotografías de rostros con su etiqueta. Sin ejemplos no hay nada que aprender.

2
🔁

Ensayo y error

Mira un ejemplo, responde, se le dice cuánto falló y se corrige. Millones de veces. Ese es todo el misterio del entrenamiento.

3
📏

Examen

Se le prueba con casos que nunca vio. Si solo acertara los que estudió, no habría aprendido: se lo habría aprendido de memoria.

4
▶️

En uso

Lo aprendido queda en un archivo. Este panel lo lee y responde en milésimas de segundo, ya sin volver a aprender.

Los pasos 1, 2 y 4 se pueden ver aquí mismo: los datos, el entrenamiento en directo y cualquiera de las demostraciones.

✅ Lo que sí hace hoy

  • Reconocer quién hay delante de una cámara y si es una persona real.
  • Leer una cédula o una constancia y sacar los datos sin teclearlos.
  • Transcribir una reunión, y leer un texto en voz alta.
  • Responder preguntas sobre nuestros propios reglamentos.
  • Anticipar ausentismo o asistencia a partir de los registros.

⚠️ Lo que conviene tener claro

  • Es la versión pequeña: modelos modestos y entrenamientos de horas.
  • Se equivoca, y lo dice: los porcentajes están calibrados, un 90 % es un 90 % de acierto real y no una confianza inventada.
  • Estima apariencia aprendida de unos datos; no determina la identidad ni ningún dato real de nadie.
  • Grabar rostros es tratar datos biométricos: hay que avisar a quien esté delante de la cámara.

Por qué corre aquí y no en la nube

  • Nada sale de la institución. Ninguna imagen, grabación ni documento viaja a internet. Con datos de personal, eso no es un detalle.
  • No se paga por uso. Un servicio externo cobra por cada consulta; esto, una vez montado, responde todas las que haga falta.
  • Aprende de lo nuestro. Un servicio genérico no conoce nuestras gerencias, nuestros formatos ni nuestro acento. Este se entrena con nuestros datos.

Y esto es a pequeña escala

Todo lo que hay aquí corre en una sola tarjeta gráfica de escritorio, con modelos pequeños y entrenamientos de un par de horas. Aun así ve, oye, habla, lee, dibuja y predice.

Con hardware dedicado la misma arquitectura escala a modelos mayores, a los datos de toda la institución y a varios entrenamientos a la vez. Lo que hoy tarda dos horas tardaría minutos, y lo que hoy es una demostración pasaría a ser un servicio en marcha.

Qué es esto

Son dos mitades separadas a propósito. Por un lado una plataforma de entrenamiento que se maneja desde la terminal o desde la pestaña Entrenar. Por otro, este panel, que solo lee los modelos ya entrenados y nunca entrena: así una cámara en vivo nunca compite por la GPU con un entrenamiento.

Instalación

La RTX 50xx es Blackwell (sm_120) y necesita PyTorch con CUDA 12.8. Las builds cu118 o cu121 no traen núcleos para esa tarjeta y fallarán.

sudo apt install python3-pip python3-venv        # esta máquina no trae pip

cd ~/Descargas/ia-genero
python3 -m venv .venv && source .venv/bin/activate

pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
pip install -r servidor/requirements.txt         # lo que necesita el panel

python preparacion/comprobar_gpu.py             # debe listar sm_120
Cuidado con facenet-pytorch: instálalo siempre con --no-deps. Sus dependencias fijan torch<2.3 y degradarían tu instalación cu128 a cu121, dejando la GPU sin núcleos utilizables.

Poner el panel en marcha

python servidor/app.py --puerto 8010

La cámara y el micrófono solo funcionan en localhost o por HTTPS: es una restricción de los navegadores, no del servidor.

El circuito completo, paso a paso

1
Conseguir datos. Desde la pestaña Entrenar, o en la terminal: 
python preparacion/descargar_dataset.py --listar
python preparacion/descargar_dataset.py --fuente fairface --max-por-clase 0
python preparacion/preparar_datos.py --val 0.15
Para cada tarea hay además un generador de datos sintéticos, para probar el circuito antes de conseguir datos de verdad.
2
Saber cuánto va a tardar antes de comprometer horas: 
python estimar_tiempo.py --config configs/genero.yaml
Mide la velocidad real de tu máquina y avisa si el cuello de botella es la CPU preparando los datos en vez de la GPU.
3
Entrenar. 
python entrenar.py --config configs/genero.yaml
python entrenar.py --preset rapido                 # prueba rápida
python entrenar.py --reanudar experimentos/genero  # continuar tras un corte
python entrenar.py --listar-opciones               # catálogo completo
Cualquier opción se cambia sin tocar archivos con --set seccion.clave=valor.
4
Evaluar y mirar el desglose por subgrupo, que es donde aparece el sesgo: 
python evaluar.py experimentos/genero --galeria
5
Usarlo en la vista correspondiente de este panel. En cuanto existe experimentos/<nombre>/mejor.pt, la vista se activa sola.

¿Se puede quemar la tarjeta?

No. La GPU baja frecuencias sola antes de dañarse, y una 5060 Ti son 180 W. Además el entrenamiento registra temperatura y consumo, y se detiene solo guardando el checkpoint si pasa de 85 °C en tres lecturas seguidas.

python preparacion/vigilar_gpu.py                  # monitor en otra terminal
python entrenar.py --set entrenamiento.temp_max=80 # más conservador
  • Por debajo de 80 °C: perfecto. Entre 80 y 84 °C: normal bajo carga.
  • Por encima de 85 °C: revisa polvo y flujo de aire, no el entrenamiento.
  • Si se corta la luz no pierdes nada: cada época guarda el estado completo y se retoma con --reanudar.

Cosas que conviene tener claras

  • Mira siempre el acierto balanceado y por subgrupo, no el global: un dataset desequilibrado da 92 % global con un desastre en la clase minoritaria.
  • Los porcentajes de las vistas están calibrados: un 90 % significa aproximadamente un 90 % de acierto real, no una confianza inventada.
  • El modelo de género estima una apariencia aprendida del dataset. No determina la identidad ni ningún dato real de nadie.
  • Grabar rostros es tratamiento de datos biométricos: informa a quien esté delante de la cámara y no almacenes las imágenes.
